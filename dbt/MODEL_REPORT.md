# Карта dbt-модели

[Основной README](../README.md) · [Подробные правила и запуск](README.md)

В репозитории реализовано **25 моделей** `stg → core → mart`.
Эта карта описывает состав модели, а не результат конкретного запуска стенда.

| Слой | Состав | Назначение |
| --- | --- | --- |
| core | 6 измерений: фильм, дата, жанр, страна, валюта, рынок | История описания фильма SCD2 и справочники |
| core | 2 моста жанров и стран | Связи конкретной версии фильма |
| core | 3 факта истории бюджета, сборов и оценок | Интервалы состояний показателей |
| core | 2 дневных факта каталога и топ-250 | Снимки накопленного охвата и полного топа |
| core current | 4 представления | Открытые версии фильмов, бюджетов, сборов и оценок |
| mart | 8 таблиц | Каталог по жанрам/странам, оценки, недельная популярность, денежные показатели и изменения топа |

Все 21 физическая таблица используют incremental-стратегию `reconcile`:
заменяются изменившиеся разделы, включая удалённые строки и исчезнувшие группы.
Чтение staging и расчёт кандидатов пока полные. Справочники, история, мосты,
снимки и витрины публикуются одной транзакцией `scripts/build.py`.
ClickHouse обновляется отдельным этапом.

Топ-250 не заполняется из ежедневного инкремента фильмов: нужен отдельный
полный снимок в `stg.top250`. Его загрузчика в проекте пока нет.
При отсутствии входа модели топа остаются пустыми.

## Как проверить результат

Лог `scripts/build.py` содержит изменения таблиц и итог прохождения data tests.
Для проверки опубликованной модели:

```bash
docker compose run --rm dbt test
docker compose exec -T --user gpadmin cloudberry bash -lc \
  'source /usr/local/cloudberry-db/cloudberry-env.sh && psql -p 7000 -d etl -v ON_ERROR_STOP=1' <<'SQL'
SELECT count(*) AS movie_versions FROM core.dim_movie;
SELECT count(*) AS current_movies FROM core.v_movie_current;
SELECT min(snapshot_date_sk), max(snapshot_date_sk), count(*)
FROM core.fact_movie_catalog_daily;
SELECT count(*) AS top250_rows FROM core.fact_top250_daily;
SQL
```

Объёмы зависят от сохранённых батчей и горизонта сборки. Наличие тестов
в репозитории само по себе не означает их успешного выполнения на текущем
стенде. Проверка повторов/full-refresh, поздних данных, rollback и других
сценариев описана в [инструкции тестирования](../tests/README.md).
